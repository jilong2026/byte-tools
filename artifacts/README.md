# artifacts/ —— 一次性产物的落脚处（不是源码）

2026-10-14 把散在仓库根的这些文件归进来，根目录因此从 49 个文件降到 15 个。

| 文件 | 是什么 | 谁在用 |
|---|---|---|
| `drill_*.json`（8 个） | 组件体检/演练的结果转储（`key` / `phase` / `check` / `ok` / `detail` 五字段的数组） | **没有任何脚本读写它们** —— 是当初做组件接入时留下的孤儿产物，全名搜遍仓库 0 命中 |
| `download_logs.txt` / `download_v3.log` / `library_logs.txt` / `official_logs.txt` | 图标采集脚本的控制台输出（「✓ deno.svg (57KB)」「成功：1/23 失败：22」这类） | **没有任何脚本读写**；已在 `.gitignore` 里忽略 |

## 别把它当证据库

`drill_*.json` 里的 `ok: true` 是**当时那次**的结果，不是当前状态。真正的结论写在
`DEVELOPMENT.md` 的规则与 `tools/` 的取证脚本里；需要重新体检就跑那些脚本。

## 以后往这里放什么

只放"一次性运行产物"（结果转储、采集日志、临时报告）。**源码、测试、脚本一律不放** ——
放进来会重新把仓库搞乱，而根目录刚收拾干净。新增的日志类文件记得同时加进 `.gitignore`
（`/artifacts/*.log` 已经覆盖 `.log`，`.txt` 之类要单独加）。
