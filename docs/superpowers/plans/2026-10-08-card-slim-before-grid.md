# 卡片瘦身方案（网格化的前置步骤）

> 状态：**已实测，待确认**。数字都是 offscreen 强制布局量出来的，不是估的。
> 结论一句话：**先瘦身、再网格化**。不瘦身直接上 2 列，一屏只有 4 个（+14%）；
> 瘦身后一屏 6 个（+71%），且窗口拉宽时自动变 3 列 9 个 / 4 列 12 个。

## 为什么必须先瘦身

原设计（`2026-10-08-ui-grid-cards-and-overlay-log.md`）用「卡片 sizeHint 624×121」推出
「2 列 × 4 行 = 8 个」。但 121 是**单行布局**的高度：把 6 个按钮塞进 313px 格子必然换行，
换行后卡片涨到 ~230，628 ÷ (230+14) ≈ 2.5 行 → **实际只有 4 个/屏**。

瘦身后按钮**不需要换行**（一行放得下 5–6 个），卡片高度只从 121 涨到 157，
628 ÷ (157+14) ≈ 3.7 → **3 行 × 2 列 = 6 个/屏**。

## 实测数字

| 项 | 现状 | 瘦身后（格子 295 / 313） |
|---|---|---|
| 卡片高度 | 121 | **157**（26 个组件全部一致，天然等高） |
| 按钮宽度 | 80–98（5–7 字 + padding 18） | 42–55（2–3 字 + padding 8） |
| 一行能否放下 5 个按钮 | 否（313 下被压到 33px 全裁字） | **能**，且全部完整无裁字 |
| 一屏个数 | 3.5 | **6**（窗口拉宽 → 3 列 9 个 / 4 列 12 个） |

按钮宽度实测公式：`13px × 字数 + padding×2`。
即 `padding 6px 18px` 时「下载并安装」= 101、「安装」= 62；`padding 6px 8px` 时 = 77 / 42。
**padding 才是大头，缩短文案是第二杠杆，两个都要动。**

## 改动清单（全在 `main.py`）

### 1. 按钮文案（`ComponentCard._build_ui` 8628 起）

| `btn_install` | 下载并安装 | **安装** | tooltip 已有完整说明 |
| `btn_configure` | 配置环境变量 / 切换为生效版本 | **切换** | 多版本语义靠 tooltip 承载 |

### 3. 顺手修一个真实缺陷：`btn_console` 没有 objectName

`_build_ui` 里 `btn_console` 没 `setObjectName`，所以 `#primaryBtn/#secondaryBtn/#dangerBtn`
三条 QSS 全都匹配不到它 —— 它拿的是系统默认样式，实测 `sizeHint` 恒为 80
（同长度的「安装」只占 42）。表现为**这颗按钮比旁边几颗都宽一圈、观感不统一**。
改法：`self.btn_console.setObjectName("secondaryBtn")`。

### 4. 卡片内部改成四行（原三行）

```
┌─ 格子 295（内部可用 271）────────────┐
│ Apache RocketMQ        [可多版本]     │  顶部行：标题(13px Bold) + 角标
│ ✓ 已配置 · 系统安装     ● 运行中 9876 │  状态行：status_label + launch_label
│ 版本 [下拉 150]                       │  版本行：版本 label(36) + combo
│ [安装][切换][卸载][启动][访问页]       │  按钮行：一行放完，不换行
│ ▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁ │  进度条 8px
└──────────────────────────────────────┘
```

原 `mid` 一行 → 拆成「版本行」+「按钮行」；`launch_label` 从按钮行尾巴提到状态行。

**注意**：原设计文档写的是「版本行 / 动作行拆两行」，与本方案一致；差异在于本方案
**同时缩短文案与 padding**，所以按钮不用换行，高度停在 157 而不是 230。

### 5. 状态文本：主文本精简，细节全部进 tooltip

实测 `status_label` 需要 448–520px，而格子只有 271px（PySide6 的 `QLabel` **没有**
`setElideMode`，超宽是直接 clip，不是省略号）。所以必须缩短文案本身。

| 场景 | 现状（太长） | 主文本改后 | tooltip |
|---|---|---|---|
| 通用已配置 | `✓ 已配置（JAVA_HOME · 系统安装，不由本工具管理） · 版本检测中…` | `✓ 已配置 · 系统安装` | 原文全量 |
| 多版本正常 | `● 已装 3 个版本 · 生效 21.0.5（21.0.5、17.0.13、11.0.25）` | `● 已装 3 个 · 生效 21.0.5` | 原文含版本列表 |
| 多版本未对齐 | `● 已装 2 个版本 · 未对齐：PATH 用的是 X，JAVA_HOME 指 Y（...）` | `● 未对齐（PATH≠HOME）` | 原文 + 具体版本 |
| 残留空目录 | `● 2 个残留空目录待清理（...） · 内容已删除、不算已装` | `● 2 个残留待清理` | 原文全量 |
| 运行状态 | `● 运行中 · 端口 9876` | `● 运行中 9876` | 原文 |

改动点：`_render_status_label`（9256）、`_detect_status_impl` 的三处胶囊赋值
（9422 / 9425 / 9429 / 9478）、`_refresh_launch_state_impl` 里 `launch_label`。
**判据字段（`_status_shows_configured` / `_mv_active` / `_mv_warned` 等）一律不动**，
只改显示文本 + 补 tooltip。

## 不能动的硬约束

- `btn_start` 文案：`_running_per_ui()`（8809）读它判断是否运行，`_mark_running_tabs`
  （10657）与 `_reveal_running_tabs`（10683）都依赖它。
- `display_name`：同时是搜索匹配（`component_matches`）与日志前缀（`_log`）的真源。
- `selections` / `active` 两个配置字段的语义与合并写（`_save_settings` 11197）。
- 按钮的 objectName 与点击行为（只改文案与尺寸，不改信号）。

## 网格化那侧要跟着改的两处

1. **`_reveal_running_tabs`（10685）会静默失效**：它用 `layouts.indexOf(card) != -1`
   判断卡片在哪个 Tab。改成行容器后卡片不在 `_tab_layouts` 里，`indexOf` 恒为 -1 →
   「有组件在跑就自动跳到那一页」直接哑掉。改用 `_tab_cards` 索引判断。
2. **`MIN_CARD_WIDTH_PX` 取 ~300，不是 470**：原设计写「640 视口 2 列，取 470」自相矛盾
   ——640 ÷ 470 只能出 1 列。要 640 下出 2 列必须取 ≈300。
3. 视图切换按钮**别放标题栏**（已有 5 个按钮 + 3 个窗口控制，实测需要 ~992px，
   再加必然裁字）；放搜索条 `search_hint` 右边的空白。

## 目测项（离线用例替代不了，实现时要如实报告）

- 100% / 125% / 150% 缩放各跑一次窗口：DPI 变大时卡片高度会涨，可能只露 2 行半。
  这是网格布局的正常滚动行为，不是 bug。
- 「访问页」按钮在运行时态会变文案，确认最长文案下按钮行不溢出。
- 状态行在 `status` 与 `launch_label` 同时非空时是否还放得下（271px 内约 250px 用量）。

## 不做

- 不给按钮加图标化 / 收进「更多」菜单（会隐藏功能入口，违背「信息一条不砍」）。
- 不改窗口尺寸（保持 1000×680、最小 1000×560）。
- 不动启停编排、`LAUNCH_KEYS`、`running.json`。
