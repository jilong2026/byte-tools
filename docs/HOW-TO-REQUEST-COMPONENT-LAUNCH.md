   端口被占时你希望：结束占用者再启动（默认） / 报错让我自己处理

【2】数据目录
   能否外移到 ~/.env-tools/<key>-data：能（环境变量 DATA_DIR=xxx）/ 不能，锁在安装目录里

【5】控制台 / 凭据

   登录凭据：账号 xxxx 密码 xxxx / 首次启动随机生成（在 xxx 文件里）/ 没有登录页
   要不要在日志里打印凭据：要 / 不要

【6】其它（可选，但说了能少一轮返工）
   官方配置文件里哪些值我改过、被你改过：
   有没有踩过的坑：

## 关键名词对照（你说这些词我就懂）

### 登记相关

| 名词 | 含义 | 你可以怎么说 |
|---|---|---|
| **LaunchSpec** | 一个组件"怎么被拉起来"的描述符，26 个组件各一份 | "给它加个 LaunchSpec" |
| **LAUNCH_OF** | 所有组件的 LaunchSpec 登记表 | — |
| **LAUNCH_KEYS** | 白名单，只有在表里的组件才有启动/停止按钮 | "把它加进白名单" |
| **风险说明 / risk_note** | 启动前弹窗里那段文字（监听地址、默认凭据） | "启动前要说清它对局域网开放" |
| **凭据 / credentials_hint** | 启动成功后打进日志的登录信息 | "启动完把账号密码打在日志里" |
| **数据去处 / data_note** | 卸载确认框里说明数据会怎样 | "卸载时要告诉用户数据在哪、会不会没" |

### 端口相关

| 名词 | 含义 | 你可以怎么说 |
|---|---|---|
| **主端口 main_port** | 组件的主端口 | "主端口 9092" |
| **派生端口 port_offsets** | 跟着主口走的口（主口 + 偏移） | "另外要用主口 +1000 和 +1001" |
| **独立端口 extra_ports** | 与主口没有固定偏移、各自找空的口 | "broker 那个 9093 单独算" |
| **端口簇 all_ports** | 主口 + 派生 + 独立，判"运行中"时整簇一起看 | "它有三个口" |
| **平移** | 端口被占时自动往后找一个空口 | **默认不启用**（见下） |
| **结束占用者** | 端口被占时把占它的进程杀掉再启动 | "被占就杀掉占用者" |
| **端口回写 port_writeback** | 改端口的方式：命令行 / 改配置副本 | "端口要写进配置副本" |
| **conf 副本** | 复制官方 conf 到我们自己的目录，只改副本 | "官方文件一个字节都不许动" |

### 停止相关

| 名词 | 含义 | 你可以怎么说 |
|---|---|---|
| **pid_role** | 登记的 PID 是服务本身还是包装器 | "我们是包装器，真正的进程是它拉起的 java" |
| **stop_kind** | 停止方式：按 PID / 厂商脚本 / 端口反查 | "厂商没有可用的关闭脚本，走端口反查" |
| **端口反查 port_lookup** | `netstat -ano` 查出谁在监听，然后结束它 | — |
| **三重闸** | ①有我们的登记 ②不是我们自己 ③用户已确认 | — |
| **僵尸** | 登记还在但端口没在听（上次崩了） | — |

## 几条你不用说我也会做的（约定俗成）

这些已经是本项目的既定做法，你不必重复：

1. **端口固定用官方默认值，被占就结束占用者，不自动平移**
   （平移会让「服务起来了但外部客户端连不上」—— Nacos 的 8848、ActiveMQ 的 61616
   都被客户端配置写死了）

2. **官方配置文件一个字节都不改**，要改只改我们自己的副本；
   锚不到要改的那一行就**拒改并告诉用户改哪一行**，不猜

3. **停止时不当场强杀** —— 先问用户，强杀可能丢未落盘的数据
   （Windows 上 `os.kill` 任何信号都是 TerminateProcess，没有"礼貌地停"这一步）

4. **认领进程时绝不结束我们自己**，同口多个 PID 时宁可不结束

5. **判"是否在运行"看整簇端口**，只看主口会把"半死"显示成运行中

6. **启动/停止是同一个按钮**：未运行显示「启动」、运行中变「停止」、点了做对应的事
   （位置固定、状态写在文字上。原来的双按钮设计让你连续三次反馈"没有停止按钮"）

7. **端口被占就结束占用者，不找替身端口**；结束不掉就指名道姓说清是谁占着

8. **一切"推测"都要实测**：端口、控制台路径、厂商 task 名、停止方式，
   没有一样能靠推理得出

## 当前进度（2026-10-06）

**已支持一键启动/停止（3/26）**：`jenkins` / `nacos` / `activemq`

**还没支持（23 个）**：
- 开发环境：`jdk` `maven` `python` `node` `git` `powershell` `conda` `go` `gradle` `bun`
- 开发软件：`tomcat` `nginx` `mysql` `mongodb` `postgresql` `rabbitmq` `kafka` `rocketmq` `pulsar` `seata` `elasticsearch`
- 其它软件：`docker` `kubectl`

> 注意：`jdk`/`python`/`node` 这类**语言运行时**通常不适合做成"启动/停止"——
> 它们是被别的程序调用的库，不是有控制台的常驻服务。
> 真正值得做的是 `kafka`/`rabbitmq`/`mysql`/`postgresql`/`elasticsearch`/`tomcat`/`nginx` 这类
> **有独立进程、有监听端口、有生命周期**的中间件。你要升级的话建议从这些里挑。

## 几个具体例子，照着改就能用

### 例 1：接一个全新的组件

> 「把 **Kafka 3.7.0** 接成一键启动停止。
> 主端口 9092，另有独立端口 9093（broker 之间通信）。
> 数据在 `~/.env-tools/kafka-data`（Kafka 的日志目录也能指过去），卸载后保留。
> 我们跑的是 `bin/kafka-server-start.sh` 包装脚本，真正的进程是它拉起的 java —— 端口反查停止。
> 没有 Web 控制台，不需要打印凭据。
> 端口被占就结束占用者。」

### 例 2：升级一个已有组件

> 「把**已有的 tomcat** 升级成可启动/停止。
> 主端口 8080，控制台路径是 `/manager/html`（Tomcat 9），凭据是安装时自己设的、没有默认值，
> 所以不用打印账号密码 —— 改成提示"凭据是你安装时设的"。
> 端口被占就结束占用者。
> 参考 Nacos 的做法做。」

### 例 3：只让我先调研、不改代码

> 「先别动代码。我想知道 **Elasticsearch** 接成一键启动要处理什么：
> 端口、数据目录、我们是不是服务进程、有没有可用的停止手段、官方配置文件里哪些值要改。
> 查完给我一份清单，我看完再决定做不做。」

### 例 4：批量做多个

> 「按 Nacos 的做法，把这三个都接上：**kafka** / **rabbitmq** / **elasticsearch**。
> 每个都先实测再写，别照推测写。做完一个给我看一次。」

## 我会按这个流程做（你可以据此检查我有没有偷懒）

1. **下载包、打开、`grep` 配置** —— 端口、路径、监听地址抄下来
2. **跑一次启动命令** —— 看它认不认那些参数（传错不报错的情况最坑）
3. **回答四个维度** —— 端口/数据/进程身份/停止手段
4. **写 `LaunchSpec` 登记**（含 `risk_note`、`credentials_hint`、`data_note`）
5. **写护栏** —— 每条语义分支配一条能区分它与旧行为的用例
6. **变异自检** —— 逐条确认护栏不是空的（这是唯一能发现空护栏的手段）
7. **真机演练** `--launch <key> --yes` —— 量启动耗时、定超时、验停止
8. **回填文档** —— 把"待实测确认"的地方全换成实测值
9. **重新打包 exe** 并核对时间戳（改源码不会自动更新 exe，这坑踩过两次）
